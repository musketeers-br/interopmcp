# Phase 1 Data Model: IRIS InteropMCP

**Feature**: specs/001-interop-mcp | **Date**: 2026-10-19

## Entities

### 1. ToolDefinition (`br.musketeers.InteropMCP.Registry` catalog view — computed + cached)

The published representation of one Business Service. Persisted as catalog cache; rebuilt
from class metadata by `BuildCatalog()` (FR-001, FR-014, SC-004).

| Field | Type | Rules |
|-------|------|-------|
| ToolName | %String | Unique across catalog (duplicate ⇒ build error, FR-014); derived from BS name |
| Description | %String | From `AIGATEWAYDESC` or default text; agent-facing |
| InputSchema | %String (JSON) | Generated by SchemaMapper from request class properties (R5) |
| Classification | %String enum | `readonly` \| `write` \| `critical` (FR-006) |
| ServiceName | %String | Config item name of the backing Business Service |
| RequestClass | %String | `Ens.Request` subclass used to build invocation payloads |
| Async | %Boolean | From `AIGATEWAYASYNC` or `AIGATEWAYWAIT` > wait window |
| Enabled | %Boolean | On/off switch; disabled tools leave the catalog (FR-013) |

### 2. ToolInvocation (`br.musketeers.InteropMCP.Invocations`, persistent)

One agent-initiated execution attempt. Audit backbone (FR-010, FR-018, SC-002).

| Field | Type | Rules |
|-------|------|-------|
| InvocationId | %String | Unique; returned to agents as processing reference |
| ToolName | %String | Must exist in catalog at call time |
| AgentIdentity | %String | Authenticated caller or `local-dev` |
| Parameters | %String (JSON) | Validated before storage (FR-012) |
| Status | %String enum | `received` → `executing` → `completed` \| `failed`; `received` → `pending-approval` → `executing` \| `rejected` |
| Result | %String (JSON) | Business response payload; empty until terminal |
| ErrorMessage | %String | Populated on `failed`/`rejected` |
| MessageHeaderId | %Integer | Native `Ens.MessageHeader` id for Visual Trace linkage |
| StartedAt / EndedAt | %TimeStamp | Duration basis for SC-002 reporting |

**State transitions**:

```text
received ──(readonly/write, authorized)──▶ executing ──▶ completed | failed
received ──(write, unauthorized)──▶ failed (denied, audited)
received ──(critical)──▶ pending-approval ──(approved)──▶ executing ──▶ completed | failed
pending-approval ──(rejected/cancelled)──▶ rejected (never executes, FR-009)
```

### 3. ApprovalRequest (`br.musketeers.InteropMCP.Approvals`, persistent)

Human decision record for critical tools (FR-009, SC-005).

| Field | Type | Rules |
|-------|------|-------|
| ApprovalId | %String | Unique |
| InvocationId | %String | FK → ToolInvocation; creation sets invocation to `pending-approval` |
| RequestedAt | %TimeStamp | Set at creation |
| Decision | %String enum | `pending` \| `approved` \| `rejected` |
| Approver | %String | Required when decision ≠ `pending` |
| DecidedAt | %TimeStamp | Required when decision ≠ `pending` |
| Reason | %String | Optional; mandatory for rejection |

No automatic expiry execution: `pending` entries remain until decided or explicitly
cancelled by an operator (spec Edge Case).

### 4. GatewaySettings (class parameters on `br.musketeers.InteropMCP.Registry`)

| Setting | Default | Purpose |
|---------|---------|---------|
| WaitWindowSeconds | 30 | Interactive wait window (FR-011; spec assumption) |
| AuthMode | `authenticated` | `unauthenticated` only when env is marked local-dev (FR-015) |
| LogLevel | `info` | Default level for `br.musketeers.InteropMCP.Log` (FR-016) |

### 5. Interop payloads (demo production, `br.musketeers.InteropMCP.Demo` package)

| Class | Extends | Properties | Used by tool |
|-------|---------|-----------|--------------|
| `br.musketeers.InteropMCP.Demo.PayLookupRequest` | Ens.Request | OrderId (%String), CustomerId (%String) | `PayLookup` (readonly) |
| `br.musketeers.InteropMCP.Demo.CustomerUpdateRequest` | Ens.Request | CustomerId (%String), NewAddress (%String) | `CustomerUpdate` (write) |
| `br.musketeers.InteropMCP.Demo.RiskCheckRequest` | Ens.Request | Cnpj (%String), Scope (%String) | `RiskCheck` (critical) |
| `br.musketeers.InteropMCP.Demo.BatchRunRequest` | Ens.Request | ReportSet (%String) | `BatchRun` (readonly, async) |

Each backing `Ens.BusinessService` carries annotation parameters (`AIGATEWAY`,
`AIGATEWAYDESC`, `AIGATEWAYASYNC`, `REQUESTCLASS`) and, on every invocation, sends the
request downstream through the native message flow: `BS → br.musketeers.InteropMCP.Demo.AuditProcess (BP) →
br.musketeers.InteropMCP.Demo.AuditOperation (BO)`. The BO persists the payload dump in `^InteropMCP.Demo.AuditD`;
the flow produces real `Ens.MessageHeader` rows (~4 per call) visible in Visual Trace.
The response is a simple `Ens.Response` subclass — pass-through to the agent.

Gateway-side audit (`br.musketeers.InteropMCP.Invocations`/`Approvals`) is separate from
the production: the MCP fires Business Services only (`CreateBusinessService` +
`ProcessInput`) and never writes into production structures; the trace is generated by the
production components themselves.

## Relationship overview

```text
BusinessService (annotated) ──1:1──▶ ToolDefinition ──1:N──▶ ToolInvocation
ToolInvocation ──1:0..1──▶ ApprovalRequest
ToolInvocation ──N:1──▶ Ens.MessageHeader (native trace)
```

## Validation rules summary

- Tool names unique; catalog build fails fast on collision (FR-014).
- Parameters validated against generated schema before persistence/execution (FR-012).
- Critical invocations can only reach `executing` via an `approved` ApprovalRequest (FR-009).
- Disabled/unavailable services are rejected at invocation and removed from catalog (FR-013).
- Every state change writes a log record at the appropriate level (FR-016).
